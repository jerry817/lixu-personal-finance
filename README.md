## AI 智能记账

- 入口：**首页 / 日历页右下角悬浮钮**。输入一句话（如「昨天午餐兰州拉面20元」）→ 识别 → 信息完整的直接入账；缺金额（或转账缺账户）的跳转记账页，已识别的字段预填；
- 识别规则：
  - **早餐 / 午餐 / 晚餐 / 夜宵是食品餐饮下各自独立的子分类**（不再有合并的「三餐」），分别记账、分别统计；一句话里有几顿就拆成几笔（「早餐8块午餐20晚餐35」= 3 笔）；
  - **日期**：昨天 / 前天 / 大前天 / 今天 / 周X / 上周X / M月D日 都会换算成账单日期；句子里只有一个相对日期词时以本地推算为准，不依赖模型的日期计算；
  - **备注只放商品/事项名**（「兰州拉面」），日期、金额、账户、餐别词、「花了/吃了」都不会进备注；没有具体名称时备注为空；
  - **账户**：用户没说就是「无账户」，不再默认微信钱包；说了（微信/vx/支付宝/招行/现金…，允许简称和错别字）才选对应账户。转账必须有明确的转出/转入账户，缺失时不自动入账，跳记账页让用户选；
  - **模糊纠错**：错别字、谐音、中文数字（「三十五块」「两百」「1.5k」）、口语省略交给大模型主动纠正和推断；可报销、已有标签也会一并识别；
- 链路：`utils/ai.js` → 云函数 `ai-recognize`（大模型）→ `ai.js` 校验。请求会带上**当前用户可用的分类树**（`store.categoryTree()`：含用户编辑过的子分类 / 改名、不含被隐藏的分类），云函数自己不带分类表；校验只在 `ai.js` 里做一次：分类必须在分类树内，不合格或云端不可用（未部署、超时、模型乱答）一律回退本地关键词规则，记账入口始终可用；
- **对账**：每次调用模型，云函数都会在日志里打一行 `[ai-recognize] 实际请求的 host model=… usage={…}`，失败时同样的信息也在报错末尾。后台查不到调用记录时，先看这里的 host 是不是你以为的那家、usage 里有没有 token 数（有 = 请求确实到了那家，后台记录可能有延迟或在别的账号 / 密钥下）。
- **部署云函数**：开发者工具右键 `cloudfunctions/ai-recognize` →「上传并部署：云端安装依赖」→ 控制台把函数**超时时间改为 10~15 秒**（默认 3 秒不够）→ 在「函数配置 → 环境变量」设置

## v1.4 变更

- **日历热力色 / 布局**（`pages/calendar`）：每日结余 = 收入 − 支出。为正 → 浅绿，为负 → 浅红，结余为 0 / 无账单不着色。深浅按 `log10(1+|结余|)` 对数刻度并缓起：几十元几乎只是一抹淡色，上千元才明显，约 1 万元及以上最深（alpha 0.05 ~ 0.32）。收入绿 / 支出红文字在任何底色上都保持原色，所以最深一档也必须是浅色调以保证可读。
  - 周一为一周起点；上月末 / 下月初的补位日期不显示（只画本月所需的 4~6 行）。
  - 每格为 1:1 圆角方块（`padding-top:100%` 实现，不依赖 `aspect-ratio`），格间距上下左右各 7rpx（相邻格相隔 14rpx）。星期表头与格列同宽对齐。
  - 选中格：纯色 `#3CB371`、无描边，格内所有文字（含收/支金额、今天标记）为白色；选中格不叠热力底色。
- **添加账户分类**：「账户 → +」先进 `account-add` 选分类（`utils/accountKinds.js` 为分类目录），再进表单。账户新增字段 `group / kind / alias / remark / cardNo / inTotal / currency`，老账户无这些字段，按 `type` 推导，编辑时保持原 `type`；`type` 口径不变（信贷分组 → `credit` 计入总负债；其余计入总资产）。
  - **简称**真正生效：AI 记账一句话里出现简称即匹配该账户（本地规则 + 云函数提示词）。
  - **计入总资产** 关闭后，该账户不进总资产 / 总负债 / 净资产（`store.getAssetSummary`），仍可记账、仍显示在账户列表。
  - 账户名称不允许重名（账单靠账户 id/名称关联）。
- **体积**：不引入任何字体文件 / 图标字体。新增 16 个品类图标为 96px 调色板 PNG，合计约 16 KB；箭头、日历图标、勾、斜线等均为纯 CSS。
- **AI 记账默认账户**：账户 chip 默认显示「上次手动选择的收支账户」（`store.lastAccountId`，与记账页共用同一份记忆；没有则「无账户」）。没动 chip 时它只补给一句话里没说账户的账单；动了 chip 则覆盖识别结果，并记住所选账户。
- **AI 记账弹窗**（`components/ai-sheet`）：首页悬浮钮 → 底部弹窗，一句话输入 + 日期 / 标签 / 账户 / 报销四个可手动指定的 chip。只有**动过**的 chip 才会覆盖识别结果（`ai.applyOverrides`），没动的仍用一句话里识别出的（如「昨天」）。点 ✓ 记账并关闭，**长按 ✓** 记账后保留弹窗继续记。日期 chip 的月历是贴屏幕底的底部面板，展开期间输入卡片整体收起、原生 tabBar 隐藏（见 v2.15），关闭后一起恢复。

## v1.7 变更（AI 记账弹窗：动效 / 二级账户菜单 / 键盘）

- **与键盘同步的上浮动画**（`components/ai-sheet`）：
  - 监听 `wx.onKeyboardHeightChange`（同时用 textarea 自带的 `keyboardheightchange` 拿 `duration`），卡片用 `transform: translate3d` 上抬（走合成层、不触发布局），`transition-duration` 取键盘动画时长，曲线用接近 iOS 键盘的减速曲线；键盘升起 / 收起时弹窗同步上浮 / 下落。
  - 记住上一次键盘高度（`ai_kb_h`）：再次打开时弹窗与键盘「同时起跳」，不再先停在底部再被顶上去；若预估后迟迟没有键盘事件（外接键盘等），0.9s 后自动收回。
  - 上抬量 = 键盘高度 − 底部安全区，卡片常驻底边距，所以键盘出现 / 消失不会产生跳变。
  - 补上进场 / 退场动画：遮罩淡入淡出，卡片上滑淡入 / 下滑淡出（退场 220ms）。页面在退场动画结束后才恢复原生 tabBar，离开页面或回到页面时还会兜底恢复一次。
- **账户选择 · 二级菜单**：点账户 chip，在卡片上方弹出「选择账户」浮层（对齐设计稿）。
  - 默认平铺：「无账户」+ 全部账户，所选项打勾。
  - 标题栏右上角的「叠放横条」图标切换为二级菜单：一级是账户分组（资金 / 信贷 / 充值…，只列有账户的分组，带数量与箭头，所选账户所在分组带绿点），点进分组后二级是该分组的账户，标题变为分组名并带返回箭头。
- **不收键盘**：textarea 与新建标签输入框都带 `hold-keyboard`；日期 / 标签 / 账户 都做成卡片上方的浮层。日期不再使用系统 `picker`（它弹出时一定会收起键盘），改为浮层月历（周一起始，带「今天 / 昨天」快捷）。浮层高度按键盘高度自适应，不会被键盘或刘海遮住。

  - 点 ✓ 识别期间不再改变焦点，键盘保持不动。

## v2.18 变更（首页导航栏高度对齐 / 下拉添加账单去抖动）

- **导航栏高度**（`pages/index`）：首页自定义导航栏原先高度 = 状态栏 + 胶囊高，比其他页（原生导航栏、`account-detail` / `bill-detail` / `deposit-*` 等自定义顶栏）矮 `(胶囊顶 − 状态栏) × 2`（约 8px），右侧搜索 / 「⋮」也没和胶囊对齐在同一水平线。现改用同一公式 `navH = (mb.top − sb) × 2 + mb.height`（取不到胶囊时 44px），`nav-row` 高度取 `navH`；`navBottom = 状态栏 + navH`。
  - 内容区顶部留白原来写死 `padding-top: 170rpx`，不同机型下导航栏与数据卡片的间距在 3~33px 之间浮动（导航栏一变高就会和下拉横幅错位）；现改为内联 `padding-top: calc(navBottom + 16rpx)`，间距固定 16rpx（同其他页）。「刷新中」药丸同样以 `navBottom + 16rpx` 定位。
- **与下拉添加账单的冲突检查**：高度本身不冲突——横幅位置只取决于 `.content` 的顶部留白，而留白现在由 `navBottom` 推出，导航栏变高后横幅 / 药丸 / 数据卡片自动跟着下移；记账触发阈值（横幅高 100px）、阻尼、上限不变。
- **下拉动画抖动**，原因与处理：
  1. **iOS 回弹补偿比原生晚一两帧**：旧实现靠 `onPageScroll` 读负的 `scrollTop`，再 `setData` 把 `pullOver` 并入横幅高度 / 负 `margin-top`，补偿总比原生回弹慢一两帧，横幅顶边与导航栏之间会闪出一条缝。现在横幅改为绝对定位、向上延伸到导航栏后面（与页面同一滚动层，随回弹同步下移），底边 = 导航栏底边 + 下拉距离；`pullOver`、`onPageScroll` 里的补偿、`margin-top` 全部删除，`onPageScroll` 只剩悬浮钮显隐。
  2. **松手瞬间跳一下**：旧实现松手时 `pullOver` 立刻清零（`margin-top` 无过渡），内容层瞬间下跳再回弹。新实现没有 `margin-top`，横幅 `height` 与内容层 `transform` 用同一时长 / 曲线（0.26s）一起回弹。
  3. **逐帧整页重排重绘**：旧实现用 `height` 把下面所有内容推开。现在内容层 `.pull-body` 只用 `transform: translateY` 下移（拖动期间 `will-change: transform`，回弹结束后撤销，避免长列表长期占用合成层）。
  4. **阈值附近文案 / 颜色来回闪**：「松开添加」加 8px 滞回（≥100px 触发，回落到 92px 以下才取消）。
  5. **起手跳 5px、往回拖时过渡反复开关**：起手后横幅高度从 0 连续增长；手指回到起点以上时高度为 0 但保持下拉状态，不再中途收起再重新起手（也就没有 10px 死区）。
  6. 高度取整像素，位置 / 状态没变化时不再 `setData`。
  7. `touchcancel` 单独处理：被系统手势 / 来电打断时只收起，不再误触发「添加」。
- 横幅静止时 `visibility: hidden`（否则 iOS 普通回弹也会露出一截绿色），回弹动画结束后由 `pullActive` 撤掉。
- 上述改动只在 `pages/index`，其他页面未动。注意：`refund` / `reimburse` / `card-setting` 的自定义顶栏用 `88rpx` 固定行高，与本公式相差几 px，本次没有改动。

## v2.21 变更（多设备数据实时同步）

- **问题**：同一账号多端使用时，一端增 / 删 / 改账单，另一端要回首页下拉刷新才能看到。原因：云端拉取只发生在「冷启动 / 首页 onShow（60 秒节流）/ 首页下拉 / 手动云同步」；`App` 没有前台恢复钩子、没有实时监听、没有定时拉取，其它页面停留时永远收不到，且后台同步完成后只刷新首页。（云同步本身并非「只上传」——`syncAll` 一直是先拉取合并再上传，缺的是下行的触发时机。）
- **实时同步**（`store.startLiveSync / stopLiveSync`，`App.onShow / onHide` 驱动，登录 / 退出登录时启停）：前台期间监听云端最新一条账单文档（`cloud.watchBills`），其它设备任何写入（含删除墓碑）几百毫秒内触发一次增量同步；监听不可用或断线时每 30 秒轮询，连上时每 2 分钟兜底轮询；断线按 5s→60s 退避重连；回到前台立即同步一次；退到后台全部停止。本机自己写入的回声事件被过滤，不会引发额外拉取。
- **页面自动刷新**：同步拉回变化后 `App.notifyDataChanged` 调栈顶页面的 `onDataChanged()`。首页 / 日历 / 统计 / 账户 / 账户详情 / 债务 / 定存 / 搜索 / 分类 / 标签 / 模板 / 报销 / 「我的」已实现；账单详情里该账单在别处被删除时提示「该账单已在其他设备删除」并退出；首页刷新保持已展开的日分组数量，不会把列表缩回第一页；记账 / 编辑类页面不实现，正在填写的表单不会被重置。
- **下行补全**：① 账户 / 预算读取失败（弱网 / 权限）以前被当成「云端没有」，随后本机旧快照会覆盖其它设备较新的设置，现在读取失败如实报错、本轮不推送；② 记账模板、首页卡片配置以前完全不同步，现在随 `user_meta` 双向同步（旧版云端文档没有这两项时保留本机的）；③ 云端已是当前版本、只是附件一直传不上去（本机文件已失效）的账单，不再每轮同步都重写云端文档。
- **需要的云端条件**：`bills` 集合 `_openid` + `syncedAt` 索引（增量拉取本来就需要，监听的升序 / 降序均可用）；监听属尽力而为，失败自动退回轮询。
